# Отчёт о приложении проверки корзины

## Коротко

В проекте теперь есть полноценный локальный интерфейс: каталог товаров, поиск и фильтр по категории, сбор корзины, ввод запроса покупателя, проверка условий, уточняющие вопросы и повторная проверка. Интерфейс сделан на React, Vite и TypeScript; локальный API написан на Python.

Приложение помогает заметить конкретные расхождения и увидеть, на каких данных основана проверка. Оно не подтверждает полную инженерную совместимость системы.

## Как запустить

Нужны два окна PowerShell. Команды выполняются из корня проекта `D:\dev\test_santeh`.

### Окно 1 — API

При использовании собственного JEV API key задай его в окружении этого окна:

```powershell
$env:JEV_API_KEY = "твой_ключ"
$env:PYTHONPATH = "src"
.\.venv\Scripts\python.exe -m seller_cart.api
```

API слушает `127.0.0.1:8000`. Если `JEV_API_KEY` не задан, API использует локальную заглушку JEV.

### Окно 2 — интерфейс

Перейди в каталог фронтенда и запусти Vite:

```powershell
Set-Location frontend
npm run dev
```

Открой адрес, который напечатает Vite. Обычно это `http://localhost:5173`. Окно с API оставь работающим: фронтенд передаёт запросы `/api` на `http://127.0.0.1:8000`.

## Как пользоваться интерфейсом

1. На вкладке «Проверка корзины» введи запрос покупателя.
2. Найди товары в каталоге и добавь нужные в корзину.
3. Нажми «Проверить корзину».
4. Посмотри общий статус, отдельные проверки, факты и источники. Если не хватает данных, интерфейс задаст вопросы; введи ответы и запусти проверку повторно.
5. В блоке «Что распознала JEV» можно посмотреть, как модель классифицировала запрос, её выбор и вероятность.

На вкладке «Каталог» можно искать товары, фильтровать их по категории, открыть карточку с характеристиками и перейти на исходную страницу товара. Кнопка «Выбрать JSON-файл» загружает другой массив карточек в текущий сеанс интерфейса. Это заменяет каталог в браузере, но не меняет файлы каталога на диске.

## Что проверяется

API формирует две проверки:

- **Совпадение диаметра.** Сравнивает размер из запроса или ответа на уточнение с диаметрами выбранных товаров.
- **Тип соединения.** Если в запросе явно назван тип соединения, сравнивает его со значениями, указанными в карточках.

Каждая проверка возвращает собственный статус, факты, источник, сообщение и рекомендацию. Общий статус — «Требуется исправить», «Нужно уточнить» или «Проверенные условия выполнены». Последний означает только то, что прошли эти две проверки; он не означает, что система полностью совместима.

Извлечение размера сначала проверяет характеристики карточки с ключом вроде «Диаметр» или «Размер», затем название товара. Поэтому размер, найденный только в названии, следует перепроверить по карточке. Сведения о материале, серии, толщине стенки, допусках, рабочем давлении и температуре не проверяются.

## JEV

JEV отвечает только на узкий вопрос о задаче покупателя. Он не определяет диаметры и не решает, совместимы ли товары. В интерфейсе выбор и вероятность показываются в отдельном блоке результата.

При наличии `JEV_API_KEY` API выполняет живой вызов. Без ключа используется локальная заглушка, что видно по названию модели в интерфейсе. Текст запроса отправляется в JEV; проверка характеристик товаров выполняется локальным API. Запуск через интерфейс показывает ответ JEV в браузере. Команда консольного CLI, если она используется отдельно, сохраняет результат в `data/res_jev.json`.

## Каталог и файлы данных

API по умолчанию читает `catalog.json` в корне проекта. При недоступности API фронтенд пытается загрузить запасной `frontend/public/catalog.json`. В обоих файлах сейчас по 60 записей.

Также в проекте есть отдельные выгрузки:

| Файл | Записей | Содержимое |
|---|---:|---|
| `data/fitingi_live.json` | 60 | выбранный подраздел фитингов |
| `data/truby-i-fitingi_live.json` | 120 | трубы и фитинги |
| `data/kanalizaciya_live.json` | 60 | канализация |

Чтобы использовать отдельную выгрузку в браузере, открой вкладку «Каталог» и загрузи нужный JSON кнопкой «Выбрать JSON-файл». Формат — JSON-массив объектов с полями карточки, например `url`, `name`, `manufacturer`, `article`, `category` и `characteristics`.

У некоторых карточек артикул отдельно не подписан, поэтому в поле `article` стоит `null`; исходные бейджи сохранены в `raw_badges`. Неизвестные характеристики не следует восстанавливать догадками.

## Что ещё важно знать

- Проверка ограничена диаметром и типом соединения. Для решения о реальном монтаже нужны инструкции производителя и оценка специалиста.
